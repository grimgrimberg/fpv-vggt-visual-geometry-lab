# Milestones 2-6: Offline Review Workflow

## Implemented Surface

- `fpv catalog sync/show/shortlist`
- `fpv media fetch`
- `fpv segment propose/accept/reject/list`
- `fpv segment contact-sheet`
- `fpv frames sample-accepted`
- `fpv vggt validate --report`
- `fpv vggt export-request`
- `fpv vggt cloud-job`
- `fpv vggt import-cloud-job`
- `fpv vggt import-bundle`
- `fpv vggt import-predictions`
- `fpv vggt run-installed`
- fail-soft `fpv reconstruct summarize`
- `fpv viz render`
- `fpv compare render`
- `fpv smooth poses`
- `fpv review audit-three`
- `fpv review run-three`
- top-level `fpv run` for synthetic runs, frame-manifest review runs, or
  video-id workflow orchestration

## Local-Only Rule

Real media and media-derived outputs belong under ignored paths such as `data/`
and `outputs/`. Do not commit downloaded videos, extracted frames, point clouds,
review HTML containing real frames, or screenshots of those pages.

## Three-Clip Smoke

The implemented comparison path accepts three or more local reconstruction
summary JSON files. A real three-clip smoke run requires:

1. three explicit `video_id` selections,
2. local media fetches,
3. accepted segment annotations,
4. sampled frames,
5. imported VGGT bundles for each segment,
6. local review HTML per segment,
7. a local comparison page.

The automated tests prove the workflow with synthetic media and mocked bundles.

## Real VGGT Handoff

The project does not call Hugging Face automatically because the public Space API
is not a stable bundle export contract. Use `fpv vggt export-request` for a
single-clip manual frame package or `fpv vggt cloud-job` for a portable
multi-clip RunPod/Colab package with relative manifests and a standalone runner.
After VGGT runs externally, return `bundles.zip`, `cloud_summary.json`, and
`cloud_run.log`, then import `bundles.zip` directly with
`fpv vggt import-cloud-job`. Alternatively, normalize converted `cameras.npz` /
`points.npz` outputs with `fpv vggt import-bundle`, or import official
`predictions.npz` exports with `fpv vggt import-predictions`.

```powershell
fpv vggt cloud-job `
  --frame-manifest <clip-a-frames.json> `
  --frame-manifest <clip-b-frames.json> `
  --frame-manifest <clip-c-frames.json> `
  --output outputs/cloud_vggt_job
```

```powershell
fpv vggt import-cloud-job `
  --source <returned-bundles.zip> `
  --output-root data/vggt `
  --report outputs/reviews/cloud_bundle_import.json
```

Once three imported bundles exist, run:

```powershell
fpv review audit-three `
  --frame-manifest <clip-a-frames.json> --bundle <clip-a-bundle> `
  --frame-manifest <clip-b-frames.json> --bundle <clip-b-bundle> `
  --frame-manifest <clip-c-frames.json> --bundle <clip-c-bundle> `
  --output outputs/reviews/real_three_clip_audit.json
```

If the audit is ready, run:

```powershell
fpv review run-three `
  --frame-manifest <clip-a-frames.json> --bundle <clip-a-bundle> `
  --frame-manifest <clip-b-frames.json> --bundle <clip-b-bundle> `
  --frame-manifest <clip-c-frames.json> --bundle <clip-c-bundle> `
  --output-dir outputs/reviews/three_clip_run `
  --smooth
```

For the friendlier wrapper that always writes `run.log`, `summary.json`, and
`NEXT_STEPS.md`, run:

```powershell
fpv run `
  --workdir outputs/reviews/three_clip_run `
  --frame-manifest <clip-a-frames.json> --bundle <clip-a-bundle> `
  --frame-manifest <clip-b-frames.json> --bundle <clip-b-bundle> `
  --frame-manifest <clip-c-frames.json> --bundle <clip-c-bundle> `
  --smooth
```

If the VGGT bundles are missing or invalid, this wrapper exits nonzero but still
writes a `needs_vggt_bundle` summary and exact next steps.

The wrapper can also start from dataset video ids after the catalog exists:

```powershell
fpv run `
  --workdir outputs/reviews/three_clip_run `
  --catalog data/catalog/catalog.parquet `
  --media-inventory data/media/media_inventory.parquet `
  --annotations data/annotations/segments.jsonl `
  --video-id <clip-a-video-id> `
  --video-id <clip-b-video-id> `
  --video-id <clip-c-video-id> `
  --fetch-media `
  --smooth
```

This path fetches only explicitly selected media, requires accepted segment
annotations before frame sampling, creates the cloud VGGT package if bundles are
missing, and renders review/comparison artifacts only after bundle validation.

After the cloud job returns `bundles.zip`, continue with the same wrapper:

```powershell
fpv run `
  --workdir outputs/reviews/three_clip_run `
  --catalog data/catalog/catalog.parquet `
  --media-inventory data/media/media_inventory.parquet `
  --annotations data/annotations/segments.jsonl `
  --video-id <clip-a-video-id> `
  --video-id <clip-b-video-id> `
  --video-id <clip-c-video-id> `
  --cloud-return <returned-bundles.zip> `
  --cloud-import-report outputs/reviews/cloud_bundle_import.json `
  --smooth
```

This imports and validates the returned ZIP before the final audit/review stage.
